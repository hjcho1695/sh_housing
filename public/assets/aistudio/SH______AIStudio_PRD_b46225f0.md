# SH 청약 비서 · Google AI Studio용 PRD (MVP)

| 항목 | 내용 |
|---|---|
| 서비스명 | SH 청약 비서 ("내 손안의 청약 비서") |
| 부서 | 시스템운영부 |
| 대상 행사 | SH 모바일 웹페이지 구축 챌린지 |
| 제작 도구 | Google AI Studio(Build) 단독 |
| 작성일 / 상태 | 2026-11-19 / 초안 v2.0 (AI Studio 제작용) |

## 0. 이 문서 사용법 (먼저 읽기)

1. 이 PRD 전체를 AI Studio 첫 프롬프트에 붙여 넣지 않는다. 기능이 많으면 AI가 한꺼번에 만들다 화면이 깨진다.
2. **11장의 앱 지침**을 Build의 시스템 지침(System instructions) 입력란에 넣는다. 입력란이 없으면 1단계 프롬프트 맨 앞에 붙인다.
3. **12장의 단계별 프롬프트 5개**를 순서대로 하나씩 입력한다. 단계마다 저장(Save)한다.
4. 나머지 장(화면·데이터·규칙)은 AI가 틀렸을 때 **확인·재요청 기준**으로 쓴다.
5. 실무 예: 3단계에서 "접수 중"이 엉뚱하게 나오면 7장 7.1 규칙을 문장 그대로 다시 붙여 넣고 "이 규칙대로만 계산해줘"라고 요청한다.

## 1. 제품 개요

- **한 문장:** 공고 3건을 탭으로 보고, 공고를 누르면 요약 카드와 일정 타임라인이 보이며, 접수 전에는 캘린더에 추가하고 접수 중에는 신청 페이지로 가는 모바일 화면
- **핵심 가치:** 공고 확인 → 일정 확인 → 캘린더 등록, 이 흐름 하나를 끝까지 동작시킨다
- **개인정보:** 하나도 받지 않는다 (휴대폰 번호 입력·문자 알림은 2단계 로드맵)

### 1.1 배경 (발표 첫 장에 쓸 수치)

1. 공고일 5.28 → 인터넷 접수 6.15~6.17: **시차 18일, 접수 기간 3일**
2. 서류심사 대상자 발표 6.26 → 서류 제출 7.1~7.3: **제출 기간 3일, 등기우편만 접수(일반우편 불가)**
3. 기존 청약공고 알리미는 유형별 구독이라 특정 공고의 접수 시작일에 맞춰 다시 알려주지 않음
4. 공고문이 긴 문서 파일 중심이라 모바일에서 일정·자격·가점 확인이 어려움

## 2. AI Studio 제작 환경과 제약

| 구분 | 내용 |
|---|---|

| 사용량 | 무료 사용량은 한국시간 오후 4~5시에 초기화 |

## 3. 범위

### 3.1 MVP (반드시 완성)

- 공고 목록: 3개 탭 + 탭별 건수 + 공고 카드
- 공고 상세: 참고용 문구 + 요약 카드 + 일정 타임라인 5단계 + "← 지금"
- 시연용 기준일 선택 → 상태 자동 전환
- 하단 고정 버튼: 접수 전 "캘린더에 추가" / 접수 중 "청약 신청하기" / 마감 "접수 마감"
- 상단 참고용 문구, 하단 AI 활용 표시, 공유 링크 동작

### 3.2 부가 (MVP 완성 후, 하나씩 저장하며)

1. ★1 놓치기 쉬운 사항 경고 카드 (약 15분)
2. ★2 주택관리번호 복사 + 공고문 원문 링크 (약 15분)
3. 자가 체크 (약 25분, 판정하지 않는 표현만)
4. 용어 풀이 (약 15분)
5. 알림 시점 선택 → 고른 시점의 캘린더 링크

### 3.3 이번에 만들지 않는 것

| 제외 항목 | 이유 |
|---|---|
| 휴대폰 번호 입력·인증번호·문자 알림 | 개인정보 수집 금지, 서버 필요 |
| 공고 4건 이상 입력 | 데이터 정확성 검수 부담 |
| 방문 접수·전자팸플릿·연관 서비스 화면 | MVP 외 |
| .ics 파일 내려받기, 알림 시점 동시 다중 선택 | 구글 캘린더 링크로 충분 |
| 공고 자동 수집, 정정 자동 발송, 관리자 입력·AI 초안 | 서버·DB 필요 → 로드맵 |
| 디자인 미세 조정 | MVP 완성 후 남는 시간에만 |

## 4. 사용자와 시나리오

- **주 사용자:** 공공주택(임대·분양) 청약을 준비하는 20~40대 모바일 이용자
- **보조 사용자:** 신혼부부, 청년, 고령자 등 공고 확인이 필요한 일반 시민

| # | 시나리오 | 확인 화면 |
|---|---|---|
| 1 | 접수 예정 공고를 보고 접수 시작일을 내 캘린더에 등록 | 목록(예정) → 상세 → 캘린더에 추가 |
| 2 | 접수 중 공고에서 바로 신청 페이지로 이동 | 목록(접수 중) → 상세 → 청약 신청하기 |
| 3 | 마감 공고의 서류 제출 일정·유의사항 확인 | 목록(마감) → 상세 타임라인 |

## 5. 화면 명세

화면은 2개뿐이다: **S1 공고 목록**, **S2 공고 상세**. 라우터 없이 `selectedId` 상태(null이면 목록)로 전환한다.

### 5.1 공통

- 폭 360~430px 모바일 기준, 한 컬럼
- 최상단 고정: **시연용 기준일** 날짜 선택 (기본 `2026-06-10`) + 작은 글씨 "시연용 기준일 - 실제 서비스에서는 오늘 날짜로 자동 적용됩니다."
- 목록 ↔ 상세를 오가도 기준일과 선택한 탭은 유지한다
- 맨 아래: "이 페이지는 생성형 AI(Google AI Studio)를 활용해 제작했습니다."

### 5.2 S1 공고 목록

| 요소 | 내용 |
|---|---|
| 탭 3개 | 청약 예정 / 접수 중 / 마감, 각 탭에 건수 표시 (예: `접수 중 1`) |
| 기본 탭 | 접수 중 (해당 건이 0이면 청약 예정) |
| 공고 카드 | 공고명, 유형, 인터넷 접수기간(`2026.06.15 ~ 06.17`), 공급 규모 |
| 상태 표시 | 예정 카드 `D-5`, 접수 중 카드 `접수 중` 배지, 마감 카드 `마감` 회색 배지 |
| 빈 탭 | "해당하는 공고가 없어요." |
| 동작 | 카드 전체를 누르면 S2로 이동 |

### 5.3 S2 공고 상세 (위에서 아래 순서)

1. **뒤로가기 버튼** (목록으로)
2. **고정 문구 바:** "요약은 참고용이며, 정확한 내용은 공고문을 확인하세요."
3. **공고 제목 + 상태 배지** (예정이면 D-Day 포함)
4. **요약 카드:** 공급 규모, 신청자격, 가점, 제출서류
5. **일정 타임라인 5단계:** 공고 → 청약 접수 → 서류심사 대상자 발표 → 서류 제출 → 당첨자 발표
   - 기간이 있는 단계는 `시작 ~ 종료`, 하루짜리는 날짜 하나
   - 해당 단계 옆에 **"← 지금"** 표시
   - 날짜가 아닌 값은 "추후 공지"
6. (부가) 놓치기 쉬운 사항 카드, 주택관리번호 복사
7. 알림 안내(5단계에서 추가): "오늘 버전은 개인정보 없이 내 캘린더에 일정을 넣는 방식이에요. 문자 알림은 준비 중입니다."
8. **하단 고정 버튼** (5.4)

### 5.4 하단 고정 버튼 (상태별)

| 상태 | 버튼 | 동작 |
|---|---|---|
| 청약 예정 | **캘린더에 추가** | 구글 캘린더 일정 추가 화면을 새 창으로 연다 (7.4) |
| 접수 중 | **청약 신청하기** | 해당 공고의 `applyUrl`을 새 창으로 연다 |
| 마감 | **접수 마감** | 회색 비활성, 클릭 불가 |

## 7. 비즈니스 규칙 (AI가 틀리기 쉬운 부분 → 문장 그대로 재요청에 사용)

### 7.1 상태 판정

날짜 비교는 **시연용 기준일 하나만** 기준으로 한다.

1. 기준일 < 인터넷 접수 시작일 → **청약 예정** (D-Day = 시작일 − 기준일, `D-5` 형식)
2. 인터넷 접수 시작일 ≤ 기준일 ≤ 인터넷 접수 종료일 → **접수 중** (시작일·종료일 모두 포함)
3. 기준일 > 인터넷 접수 종료일 → **마감**

### 7.2 날짜 계산 주의

- `YYYY-MM-DD` 문자열을 `new Date()`로 바로 비교하지 않는다. 시간대 때문에 하루가 어긋난다.
- **UTC 기준 일 단위 숫자**(예: `Date.UTC(y, m-1, d) / 86400000`)로 바꿔서 비교하고 D-Day를 계산한다.
- 정규식 `^\d{4}-\d{2}-\d{2}$`에 맞지 않는 값(예: `2026-08-○○(예시)`)은 **계산에서 제외**하고 화면에 "추후 공지"로 표시한다.

### 7.3 타임라인 "← 지금" 위치

| 단계 | 사용 데이터 |
|---|---|
| 1 공고 | `noticeDate` |
| 2 청약 접수 | `internetStart` ~ `internetEnd` |
| 3 서류심사 대상자 발표 | `docResultDate` |
| 4 서류 제출 | `docSubmitStart` ~ `docSubmitEnd` |
| 5 당첨자 발표 | `winnerDate` |

1. 기준일이 어떤 단계의 기간(시작~종료)에 들어가면 그 단계에 표시한다.
2. 어느 기간에도 속하지 않으면, 기준일 이후 가장 가까운 다음 단계에 표시한다.
3. 날짜가 아닌 단계는 계산 대상에서 제외한다.
4. 계산 가능한 단계가 모두 지났으면 표시하지 않는다. (대안: 첫 날짜 미정 단계에 표시 → 팀이 결정)

**검증 (공고 ① 기준)**

| 기준일 | "← 지금" 위치 | 이유 |
|---|---|---|
| 2026-06-10 | 청약 접수 | 기간 밖, 다음 단계 |
| 2026-06-16 | 청약 접수 | 6/15~6/17 안 |
| 2026-07-02 | 서류 제출 | 7/1~7/3 안 |

### 7.4 구글 캘린더 링크 (접수 전 버튼)

- 형식: `https://calendar.google.com/calendar/render?action=TEMPLATE&text=제목&dates=YYYYMMDD/YYYYMMDD&details=설명`
- `text`: `[SH 청약] {공고명} 접수 시작`
- `dates`: 종일 일정. 시작 = 인터넷 접수 시작일, 종료 = **시작일 다음 날** (종일 일정은 종료일이 배타적이기 때문)
- `details`: `접수기간 {시작~종료} / 신청: {applyUrl} / ※ 정확한 내용은 공고문을 확인하세요.`
- 한글은 `encodeURIComponent`로 인코딩한다.
- 외부 API·키는 쓰지 않는다.

실무 예 (공고 ①): 접수 6/15~6/17이면 `dates=20260615/20260616`. 사용자 캘린더에 6/15 종일 일정 1개가 생긴다.

## 10. 비기능 요구사항

1. **개인정보:** 입력칸(전화번호·이메일·이름)·로그인·저장을 만들지 않는다. 5단계에서 AI에게 한 번 더 점검시킨다.

5. **시연 표시:** "시연용 기준일"임을 화면에 분명히 표시해 실제 기능으로 오해하지 않게 한다.
