# SH 청약 비서 · 관리자 페이지 AI Studio 프롬프트 키트

## 0. 이 페이지가 하는 일

1. 담당자가 공고문(PDF 또는 붙여넣은 텍스트)을 올린다.
2. AI가 사용자 화면에 쓰이는 양식(공고 데이터 JSON)에 맞춰 **초안**을 채운다.
3. 담당자가 원문 근거를 보며 수정하고 검수 체크 후 저장한다.
4. 저장한 공고는 사용자 화면 데이터(`NOTICES`)에 그대로 붙여넣을 JSON으로 내보낸다.

**실무 예시:** 1차 행복주택 공고문 PDF를 올리면 인터넷 접수 6.15~6.17, 서류 제출 7.1~7.3이 자동으로 채워진다. 옆에 원문 문장이 근거로 함께 뜨니, 담당자는 문장과 날짜를 눈으로 맞춰 보고 저장만 누르면 된다.

## 1. 먼저 정해진 설계 (DB 없이 만드는 방법)

- **저장:** 브라우저 `localStorage`. 서버·DB는 쓰지 않는다.
- **사용자 화면과 연결:** 관리자 앱과 사용자 앱은 AI Studio에서 서로 다른 앱이라 저장소를 공유하지 못한다. 그래서 **[JSON 복사] → 사용자 앱의 `NOTICES`에 붙여넣기**로 연결한다. 오늘 이 방식이 가장 안전하다.
- **AI 정리:** Build 앱에 기본 제공되는 Gemini 호출을 쓴다. 키를 코드에 직접 쓰지 않는다.
- **원칙:** AI 결과는 **초안**이다. 담당자가 "원문 대조 완료"를 체크해야 저장할 수 있다.
- **새 앱으로 만든다.** 사용자 화면 앱(MVP)에 섞지 않는다. MVP 완성 전에는 이 키트를 시작하지 않는다.

> 해당 자료에 "결과물에 DB 등 외부 프로그램 사용 불가"라는 조건이 있으므로, 위 방식이 조건 안에서 가능한 최대치입니다. 자동 반영은 로드맵(8장)으로 넘깁니다.

## 2. 사용 전 체크

- [ ] 사용자 화면 앱의 공고 데이터 JSON 필드를 그대로 쓴다 (3장)
- [ ] 테스트용 공고문 파일 1~2개를 PDF로 준비한다 (HWP는 업로드되지 않으므로 PDF로 변환하거나 본문 텍스트 복사)
- [ ] 개인정보가 들어간 문서는 올리지 않는다 (**공개된 공고문만**)
- [ ] 단계마다 **Save**, 깨지면 직전 버전 **Restore** 후 더 작게 나눠 재요청

## 3. 데이터 양식 (사용자 화면과 동일, 1단계에 붙여넣기)

```json
{
  "id": 1,
  "name": "공고명",
  "type": "행복주택",
  "noticeDate": "YYYY-MM-DD",
  "internetStart": "YYYY-MM-DD",
  "internetEnd": "YYYY-MM-DD",
  "visit": "방문 접수 일정 또는 없음",
  "docResultDate": "YYYY-MM-DD",
  "docSubmitStart": "YYYY-MM-DD",
  "docSubmitEnd": "YYYY-MM-DD",
  "winnerDate": "YYYY-MM-DD 또는 추후 공지",
  "supply": "000호",
  "eligibility": "신청자격 2~3줄 요약",
  "points": "가점 2~3줄 요약",
  "documents": "제출서류",
  "caution": "놓치기 쉬운 사항",
  "houseNo": "주택관리번호",
  "noticeUrl": "공고 게시글 주소",
  "applyUrl": "신청 주소"
}
```

**관리자 전용 값(내보내기에서 제외):** `evidence`(필드별 원문 근거), `confidence`(확신도), `reviewed`(검수 여부), `updatedAt`

## 4. 단계별 프롬프트

### [1단계] 공고 목록 + 수동 입력·저장 · 0:30

```
SH 청약 비서의 관리자용 웹페이지 "청약 비서 관리자"를 만들어줘. PC 화면 기준이고 휴대폰에서도 깨지지 않게 해줘.
- 왼쪽: 저장된 공고 목록 (공고명, 유형, 인터넷 접수기간, 검수 상태 배지 "검수 전/검수 완료"), 맨 위에 "새 공고 추가" 버튼
- 오른쪽: 선택한 공고의 편집 양식. 아래 데이터 양식의 항목을 모두 입력칸으로 만들어줘.
  · 날짜 항목은 날짜 선택, 긴 요약 항목은 여러 줄 입력칸
  · 모든 입력칸 위에 항목 이름을 한국어로 표시
- 맨 아래 고정 영역: "저장", "삭제" 버튼
- 저장한 공고는 브라우저 localStorage에 보관해서 새로고침해도 남게 해줘.
- 외부 서버, DB, 로그인, 개인정보 입력칸은 만들지 마. 아직 AI 기능은 만들지 마.
[3장 데이터 양식 붙여넣기]
```

**Plan B:** 목록이 복잡하면 목록 없이 "공고 1건 편집 + 불러오기/저장"만 먼저 만든다.

### [2단계] 공고문 업로드 + AI 초안 · 1:00

```
편집 화면 맨 위에 "공고문 업로드" 영역을 추가해줘.
- PDF 파일 올리기 또는 공고문 본문 텍스트 붙여넣기 중 선택. 파일은 PDF와 텍스트만 받고, 다른 형식은 "PDF로 변환하거나 본문을 붙여 넣어 주세요"라고 안내해줘.
- "AI로 정리하기" 버튼을 누르면 Gemini에게 아래 [AI 지시문]과 함께 공고문을 보내고, 결과를 JSON으로 받아 양식의 각 입력칸에 채워줘.
- 처리 중에는 "정리 중입니다" 표시, 실패하면 "정리하지 못했어요. 직접 입력하거나 다시 시도해 주세요"를 보여주고 기존 입력값은 지우지 마.
- AI가 채운 칸은 연한 파란색 테두리로 구분해서, 담당자가 고치면 일반 테두리로 바뀌게 해줘.
- 이미 입력된 칸이 있으면 덮어쓰기 전에 "기존 내용을 AI 결과로 바꿀까요?"를 물어봐.
- API 키를 화면이나 코드에 직접 쓰지 마. 개인정보 입력칸도 만들지 마.
[AI 지시문 붙여넣기 - 5장]
```

**Plan B:** PDF 업로드가 안 되면 텍스트 붙여넣기만 지원한다. 그래도 안 되면 AI 정리 없이 1단계 수동 입력으로 진행하고, 발표에서는 사전 AI Studio 채팅 요약 결과를 소개한다.

### [3단계] 원문 근거 + 확신도 표시 · 1:20

```
AI가 돌려주는 결과에 항목마다 "원문 근거"(공고문에서 찾은 문장)와 "확신도"(높음/보통/낮음/못 찾음)를 함께 받아서 화면에 보여줘.
- 각 입력칸 아래에 작은 글씨로 원문 근거를 보여주고, "못 찾음" 항목은 입력칸을 비워 두고 노란 배경으로 표시해줘.
- 확신도가 "낮음"인 항목은 주황색 "원문 확인" 태그를 붙여줘.
- 화면 위에 요약 줄을 넣어줘: "자동 입력 12개 · 원문 확인 필요 3개 · 못 찾음 2개"
- 원문 근거는 저장 데이터에는 보관하되, 사용자 화면용 JSON 내보내기에는 포함하지 마.
```

### [4단계] 입력값 점검 + 검수 후 저장 · 1:40

```
저장하기 전에 아래를 자동으로 점검해서 편집 화면 위에 보여줘. 오류가 있어도 저장은 막지 말고, 담당자가 "그래도 저장"을 고르게 해줘.
1. 날짜 순서: 공고일 ≤ 인터넷 접수 시작 ≤ 종료 ≤ 서류심사 대상자 발표 ≤ 서류 제출 시작 ≤ 종료 ≤ 당첨자 발표
2. 날짜 형식: YYYY-MM-DD가 아니면 "날짜가 아닌 값은 사용자 화면에 '추후 공지'로 표시됩니다"
3. 비어 있는 필수 항목: 공고명, 유형, 인터넷 접수 시작·종료, 공급 규모
4. 요약 길이: 신청자격·가점·제출서류·놓치기 쉬운 사항이 각각 120자를 넘으면 "모바일에서 길어요" 경고
저장 버튼 위에 "공고문 원문과 대조했습니다" 체크박스를 넣어줘. 체크하지 않으면 저장은 되지만 상태를 "검수 전"으로 두고, 체크하면 "검수 완료"로 바꿔줘.
```

### [5단계] 사용자 화면 미리보기 + JSON 내보내기 · 1:50

```
편집 화면에 두 가지를 추가해줘.
1. "사용자 화면 미리보기" 버튼: 지금 입력된 값으로 모바일 폭의 공고 카드와 요약 카드(공급 규모·신청자격·가점·제출서류)를 팝업으로 보여줘. 상단에 "요약은 참고용이며, 정확한 내용은 공고문을 확인하세요." 문구도 넣어줘.
2. "사용자 화면용 JSON 복사" 버튼: "검수 완료"인 공고만 모아 JSON 배열로 클립보드에 복사하고 "복사됐어요"를 2초간 보여줘. evidence, confidence, reviewed, updatedAt은 빼줘. "검수 전" 공고가 있으면 "검수 전 공고 N건은 제외했어요"라고 알려줘.
그리고 화면 맨 아래에 "이 페이지는 생성형 AI(Google AI Studio)를 활용해 제작했습니다." 문구를 넣어줘. 기능은 더 추가하지 마.
```

## 5. AI 지시문 (2단계에 붙여넣기)

```
너는 공공주택 입주자 모집공고문에서 정보를 뽑는 도우미야.
아래 규칙을 반드시 지켜.
1. 공고문에 적힌 내용만 사용해. 없는 내용은 추측하거나 만들지 말고 값을 빈 문자열로 두고 확신도를 "못 찾음"으로 표시해.
2. 날짜는 YYYY-MM-DD로 바꿔. 연도가 없으면 공고일의 연도를 사용해. 날짜가 확정되지 않았으면 "추후 공지"라고 써.
3. 인터넷 접수, 방문 접수, 서류심사 대상자 발표, 서류 제출, 당첨자 발표를 서로 헷갈리지 마. 비슷한 날짜가 여러 개면 확신도를 "낮음"으로 표시해.
4. 신청자격, 가점, 제출서류, 놓치기 쉬운 사항은 시민이 휴대폰에서 읽기 쉬운 쉬운 말로 각각 2~3줄(120자 이내)로 요약해. 공고문 문장을 길게 그대로 옮기지 마.
5. 놓치기 쉬운 사항에는 접수 방법 제한(예: 등기우편만 접수), 짧은 기간, 기존 예비자 불이익, 서류 제출 마감 같은 항목을 우선 넣어.
6. 항목마다 근거가 된 원문 문장(evidence)을 그대로 짧게 적어줘.
7. 아래 항목 이름의 JSON만 돌려줘: name, type, noticeDate, internetStart, internetEnd, visit, docResultDate, docSubmitStart, docSubmitEnd, winnerDate, supply, eligibility, points, documents, caution, houseNo. 각 항목은 {value, evidence, confidence} 형태야.
8. 소득·자산 금액, 가점 점수처럼 숫자가 틀리면 시민에게 피해가 가는 값은 확신이 조금이라도 부족하면 "낮음"으로 표시해.
```

## 6. 완성 체크

- [ ] 공고를 추가·수정·삭제할 수 있고 새로고침해도 남는다
- [ ] PDF 또는 텍스트를 올리고 "AI로 정리하기"를 누르면 양식이 채워진다
- [ ] AI가 채운 칸이 구분되고, 칸마다 원문 근거가 보인다
- [ ] "못 찾음"·"낮음" 항목이 눈에 띄게 표시된다
- [ ] 날짜 순서 오류를 경고한다 (일부러 시작일을 종료일보다 늦게 입력해 테스트)
- [ ] "원문 대조" 체크 없이는 "검수 완료"가 되지 않는다
- [ ] 미리보기가 사용자 화면의 카드 모양과 비슷하다
- [ ] 복사한 JSON을 사용자 앱의 `NOTICES`에 붙여넣으면 3개 탭에 그대로 나온다

## 7. 연결 방법 (사용자 앱에 반영)

1. 관리자 앱에서 [사용자 화면용 JSON 복사].
2. 사용자 앱의 AI Studio 채팅에 아래 프롬프트와 함께 붙여넣기.

```
코드 맨 위의 공고 데이터(NOTICES)를 아래 JSON으로 통째로 교체해줘. 다른 코드는 바꾸지 마.
각 항목의 키 이름은 그대로고, 날짜가 아닌 값은 기존 규칙대로 "추후 공지"로 표시해줘.
[JSON 붙여넣기]
```

## 9. 주의사항

- **AI 오류가 가장 큰 위험:** 날짜 하나가 틀리면 시민이 청약을 놓친다. 검수 체크 없이 내보내지 않는다.
- **공개 공고문만 업로드:** 개인정보·내부 문서는 올리지 않는다.
- **브라우저 저장 한계:** `localStorage`는 브라우저를 바꾸거나 기록을 지우면 사라진다. 확정본은 JSON을 메모장에도 보관한다.
- **화면이 깨질 때:** 여러 번 고치려 하지 말고 직전 버전 Restore 후 더 작게 나눠 재요청한다.
- **시간 우선순위:** 사용자 화면 MVP(8개 기준)가 먼저다. 이 관리자 페이지는 MVP 완성 후 남는 시간에 1·2단계부터 만든다.
